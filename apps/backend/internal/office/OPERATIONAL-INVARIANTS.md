## Traps

- **Routine work is not generic monitoring.** Taskless routine prompts resolve the registered routine identity and description from their persisted wake context. Heavy tasks in an Office workspace's same-workspace, system-owned builtin Routine workflow retain Office identity and use the Office runtime surface. Optional `task_template.required_subtask_count` is a trusted create-time minimum; all task-state writes and Done-step entry use the task repository transaction that checks durable task-specific runner assignments. Detail and bounded batch completion reads share that check. Do not replay existing runs or reopen completed tasks when enabling the opt-in.

- **Run records are owned by `internal/runs/models`.** Office owns the meaning and policy for causation, priority, launch safety, and provider routing; the shared `Run`/`RunEvent` data shapes belong to runs. `office/models` retains compatibility aliases while its consumers migrate. `GateFailureState`, `CausationRefusalEntry`, and `ContinuationScopeForRun` remain Office-owned. See ADR `2026-09-26-run-contract-ownership`.
- **A run is not a task start.** The `runs` table carries provider routing (`resolved_provider_id`, `logical_provider_order`, `requested_tier`, plus the `office_run_route_attempts` ledger), the per-reason `assembled_prompt`, the `AppendRunEvent` timeline, and retry/backoff/coalescing (`retry_count`, `earliest_retry_at`, `coalesced_count`, `idempotency_key` with unique index `idx_run_idempotency`). `Service.QueueRun` (`service/run.go`) and `SchedulerService.QueueRun` (`scheduler/run.go`) are the entry points that populate all of it; `TaskStarter` (the `StartTask` seam office calls, `service/service.go`) runs only *after*. Calling `StartTask` directly, or any ordinary kanban start path, skips all of the above. See `scheduler.md`.
- **Trace wakeup ownership before choosing an entry point.** The producer owns whether accepted intent survives a pause. The queue or recovery path owns replay. The shared dispatcher owns run creation, routing, coalescing, and retry policy. Low-level run admission only starts an admitted run; it does not replace those contracts. Record the producer's pause policy and replay owner before tracing a lifecycle path. A source whose contract skips work while paused does not require retained intent.
- **Run-owned sessions are not task sessions.** `office_run_sessions` records one immutable execution attempt per `(run_id, attempt)` and is reserved while the run is claimed. `runtime.LaunchSpec.Owner` carries that identity through lifecycle events; a retry gets a new run-session ID and delayed predecessor events must not finish or charge the successor.
- **Periodic wake classification:** `heartbeat` is retired as a wake source, but legacy heartbeat reasons remain in stored runs and routing policy. `shared.IsPeriodicTasklessWake` treats `RunReasonRoutineDispatchCron` and `RunReasonHeartbeat` as periodic. Manual and webhook routine dispatches use `RunReasonRoutineDispatchEvent` and never idle-skip. The legacy `RunReasonRoutineDispatch` is not skippable because its trigger is unknown. Coalescing promotes a queued periodic run to an event reason; it never changes a claimed run. An event that meets a claimed periodic run creates a separate run. Check the run reason and coalescing state before changing idle-skip behavior.
- **Continuation summary scope:** `models.ContinuationScopeForRun` computes the scope when the run is created. `refreshContinuationSummary` reads the persisted `run.ContinuationScope`; never recompute it from a later context snapshot. Scopes use `routine:<id>` or `agent:<id>`; the legacy `"heartbeat"` scope is retired.
- **Participant slate: one builder, not office's own.** The AC-50 slate construction lives in `internal/workflow/engine` — `(*Engine).requiredSeats` / `requiredSeatsForWorkflow` (`workflow/engine/quorum.go`) — and `ResolveParticipantRole` (same file) reuses it so role resolution and slate membership can never disagree about who participates. Office reaches it through `engine_dispatcher.Dispatcher.ResolveParticipantRole`, which forwards verbatim. Do not add an office-local "who are this task's reviewers" query; that is a fourth answer to a question that already has exactly one.
- **Lightweight vs. heavy routines fail differently.** A routine with an empty `task_template` (`routines/service.go`; `CreateDefaultCoordinatorRoutine` sets `TaskTemplate: ""`, cron `*/5 * * * *`) is lightweight. Its **idle skip** — firing with no actionable task, launching nothing — is specified behavior (`scheduler.md`, telemetry `wakeup_idle_skipped`), not a bug; don't "fix" it. `checkIdleSkip` fails **open** on a DB error.
- **A new Office HTTP route must declare how it is scoped.** Office routes are keyed by a resource id far more often than by `:wsId`, so `officeWorkspaceScopeMiddleware` (`internal/backendapp/office_scope.go`) resolves the route's own ids to their owning workspace before dispatch — do not add a per-handler ownership check instead. A route naming a resource kind with no resolver is **denied**, and `TestOfficeRouteScopeCompleteness` turns that into a build failure. Adding a route means one of: register a `WorkspaceIDFor...` lookup in `office/repository/sqlite/workspace_scope.go` plus its `<collection>/:<param>` entry in `officeParamScopeResolvers`; list a child param in `officeScopedSubResourceParams`; or add it to `officeWorkspacelessRoutes`/`Prefixes` with the reason.
- **Authorize every route ID.** The scope guard checks `:wsId` and every other resolvable parameter. Do not rely on the workspace path alone.
- **Scope agent callers.** `AgentAuthMiddleware` checks the token workspace against `:wsId` only. `authorizeOfficeAgentCaller` also resolves ID-based routes and requires every workspace to match the token. Do not bypass it for callers in context.
- **Keep route IDs in one workspace.** `officeRouteWorkspaces` rejects routes whose IDs resolve to different workspaces, even when the caller owns both. `TestOfficeMultiIDRoutesRejectMixedWorkspaces` covers registered routes.
- **Resolvers must fail closed.** They deliberately do not reuse `GetTaskWorkspaceID`/`GetProjectWorkspaceID` (`repository/sqlite/tasks.go`) — those return `("", nil)` for a missing row, and `AuthorizeWorkspaceAccess` reads `""` as "no scoping applies", i.e. allow everything.
- **`workflow_step_id` in a run payload opts the run into staleness cancellation.** `evaluateRunStaleness` (`service/scheduler_staleness.go`) cancels a run whose payload `workflow_step_id` no longer matches the task's step; runs without it are exempt. The runs service therefore records the queue-time step of a step-less task run under a separate key, `runsmodels.QueuedWorkflowStepPayloadKey` (`queued_workflow_step_id`), read only by the author-provider lookup. Do not "simplify" that into `workflow_step_id`.
- **Advancement has two signals.** An explicit `step_complete_kandev` MCP call (registered `mcp/server/server.go`, ADR 0015) and the turn-end path (`handleAgentReady`, `orchestrator/event_handlers_agent.go`), reconciled for late signals in `orchestrator/event_handlers_step_completion.go`. The per-step toggle `auto_advance_requires_signal` (`mcp/server/config_handlers.go`) couples them — know which one a step relies on before changing either.
- **Office seat reads are workflow-scoped like the engine slate — except one.** `ListTaskParticipants`/`ListAllTaskParticipants` (`repository/sqlite/participants.go`, via shared `listWorkflowScopedSeats`) return a per-task seat cast at any step of the task's current workflow, mirroring the engine's `gatherParticipantSlate`, not just the task's current step — a step move must not drop a reviewer/approver from the task DTO, inbox, decision authorization, or the approval gate (AC-OFFICE-SEAT-READ-SCOPE-001.1). `AddTaskParticipant`'s `probeExistingIdentity` is widened the same way, so re-registering an identity already seated elsewhere in the workflow is a no-op, not a duplicate (AC-OFFICE-SEAT-READ-SCOPE-001.2). The one deliberate exception is `retainsTaskCapacity` (`dashboard/service_tasks.go`), which reads the separate, still step-scoped `ListTaskParticipantsAtCurrentStep` — AC-OFFICE-SESSION-TERM-002.3 requires session-termination capacity to stay bound to the current step, since a stale seat naming a previous occupant must not suppress a termination forever. Don't "fix" that call site to use the workflow-scoped method.
- **Config sync's mutual-exclusion guard is wired import-free.** `configsync.Service` is the single source of truth for whether a workspace has an active config-sync source (`HasActiveSource`), and it must refuse `office/config`'s `ApplyImport`/`ApplyIncoming`/`ApplyOutgoing` and `office/dashboard`'s git clone/pull while active. Neither consumer package imports `configsync`: each declares its own local, exported `ActiveSourceChecker` interface (`HasActiveSource(ctx, workspaceID) (bool, error)`), and `routes.go` is the sole composition root that satisfies it with `svcs.ConfigSync`. Assign through an interface-typed local variable there (`var guard config.ActiveSourceChecker; if svcs.ConfigSync != nil { guard = svcs.ConfigSync }`) rather than passing the concrete `*configsync.Service` pointer straight into the constructor — a nil concrete pointer assigned directly to an interface parameter produces a non-nil interface wrapping nil, which a `guard == nil` check inside the handler package would miss.
