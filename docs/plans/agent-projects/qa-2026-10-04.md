## Confirmed issues

### QA-01: Project tasks appear twice in navigation (high)

**Reproduce:** Create a project. Open desktop navigation or the phone menu.
The coordinator appears in Projects and again in the ordinary Tasks list.

**Cause:** The sidebar query excludes automation and configuration tasks but
does not exclude Agent Project membership. The legacy workspace list already
has that exclusion.

**Contract:** The Projects system design requires exclusion from ordinary
sidebar/board lists. See AC-PROJECTS-AGENT-PROJECTS-004.3 and 005.1.

**Repair:** Add the membership exclusion to the shared sidebar query. Test a
mixed collection containing ordinary tasks, a coordinator, and a worker.
Verify desktop and phone navigation after create and reload.

**Status:** Fixed. Regression checks are listed below.

### QA-02: Desktop form controls exceed the shared size (medium)

**Reproduce:** Open Create/Edit project on a desktop with a fine pointer.
The name field, four selects, Cancel, and submit each measure 32px.
The shared ordinary-control contract requires 28px.

**Cause:** Form callers override the shared density with `h-8`; raw fields
also bypass the shared coarse-pointer sizing helper.
The tablet form's close button also measures only 24px.

**Repair:** Reuse shared control sizing. Measure desktop heights, phone
heights, and coarse-pointer tablet heights. Keep selection rows sized for
their content.

**Status:** Fixed. Regression checks are listed below.

### QA-03: Phone project navigation has a small hit area (medium)

**Reproduce:** Open the phone navigation menu. The project-name button measures
21.125px high, although its parent row is 44px high. Tapping the row's vertical
padding does not open the coordinator. The Projects section-label button is
also only 17.875px high.

**Cause:** The child buttons retain intrinsic height; parent spacing does not
increase their active hit areas.

**Contract:** AC-PROJECTS-AGENT-PROJECTS-005.2 and the shared touch sizing rule.

**Repair:** Give the project opener its actual row height. Ensure the section
header fits its touch action and provides a 44px section toggle. Verify target
geometry, containment, and a tap near the bottom edge.

**Status:** Fixed. Regression checks are listed below.

### QA-04: Phone confirmation is capped at 80% height (medium)

**Reproduce:** Open Delete project at 393×851. The surface measures 680.797px
and starts at y=170.203. Archive uses the same frame.

**Cause:** The Drawer primitive's direction-specific `max-h-[80vh]` overrides
the caller's unqualified maximum height. Its inset background also remains.

**Contract:** UI-05 requires a full-height phone confirmation. UI-04 requires
a focused full-height form with internal scrolling and a safe-area footer.

**Repair:** Override the matching primitive geometry and background for both
phone surfaces. Keep one internal form/confirmation scroll owner and fixed
actions. Verify viewport bounds and touch targets at phone widths.

**Status:** Fixed. Regression checks are listed below.

### QA-05: Repository selector asks for a profile (low)

**Reproduce:** Open Create project before selecting a repository. The Primary
repository field displays “Choose a profile”.

**Cause:** The select component uses a profile-specific placeholder for every
field.

**Repair:** Use the existing translated repository-selection label for this
field, and retain the profile placeholder for agent fields.

**Status:** Fixed. Regression checks are listed below.

### QA-06: Desktop form padding is inconsistent (low)

**Reproduce:** Open Create project at 1280×720. Header content starts 16px from
the dialog edge; fields and footer actions start 32px from it. The body adds
padding inside the dialog's existing padding.

**Repair:** Align desktop header, fields, and footer on the dialog's existing
inset. Keep the phone body's 16px inset. Measure rendered alignment.

**Status:** Fixed. Regression checks are listed below.

### QA-07: A later coordinator profile edit blocks an existing session (high)

**Reproduce:** Create with coordinator A. Change the project to B, then open
its coordinator to prepare a session pinned to B. Change the project back to
A. Press Start agent in the existing B session. It fails with “agent project
task creation is only available through the project service”.

**Cause:** Launch admission recognizes the current configured profile and the
task's original profile. It does not recognize a different profile already
pinned to a legitimate existing coordinator session.

**Contract:** AC-PROJECTS-AGENT-PROJECTS-001.3 requires existing sessions to
retain their assigned profile after project edits.

**Repair:** Distinguish a new session from a server-loaded existing session at
project launch admission. Validate task/session membership and retain the
existing session's stored profile. New sessions use the current configured
coordinator profile; worker profiles remain pinned. Do not accept a caller's
arbitrary profile or session identity. Cover A→B→A, new versus existing
sessions, forbidden replacements, and unavailable pinned profiles.

**Status:** Fixed. Regression checks are listed below.

### QA-08: Pending context responses can affect another project (high)

**Reproduce:** Start saving a context file in project A. Switch the mounted
context panel to project B before the save returns. The old response restores
A's file in B's panel. A pending file read can also leave B's controls busy.
Deferred-response hook tests reproduce both failures.

**Cause:** Context reads use a generation guard, but saves do not. Directory
loading invalidates a read without clearing its busy state.

**Contract:** AC-PROJECTS-AGENT-PROJECTS-003.1 and the project context isolation
boundary. A displayed file must belong to the currently selected project.

**Repair:** Guard save completion, errors, and busy cleanup by the current
generation. Clear the previous operation's busy state on directory/project
navigation. Test deferred success, deferred failure, and current-project
operations while the old request finishes.

**Status:** Fixed. Regression checks are listed below.

### QA-09: New session selects an ineligible project profile (high)

**Reproduce:** Run a coordinator session with profile B. Change the project
coordinator to A. Open New Session. Its generic profile selector retains B
from the current session or recent use. Starting fails at project admission.
It also offers unrelated profiles that the project service must reject.

**Cause:** The ordinary new-session profile selection does not apply the
project's current coordinator profile or the worker's pinned profile.

**Contract:** AC-PROJECTS-AGENT-PROJECTS-001.3. New coordinator sessions use
the current configuration; existing sessions retain their profile.

**Repair:** Restrict project new-session choices to the allowed profile.
Preserve ordinary-task profile selection. Fail closed when project identity
or configuration is unavailable. Test both coordinator and worker selection,
plus an actual existing-B and new-A browser launch.

**Status:** Fixed. Regression checks are listed below.

## Limits

This audit covers Chromium desktop, Android-style phone emulation, and a
touch-enabled tablet context. It does not certify Safari, a physical phone,
or the Tauri desktop shell.

Agent responses and GitHub services use mocks. Repository, workspace, MCP,
context, task, session, and project operations run through the real backend.
Provider credentials, real-model behavior, and external-service outages were
not tested. The injected creation failure verifies draft retention and retry.
