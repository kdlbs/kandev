## Findings

### F1. P1 blocker: Local and scratch attachment returns success without materialization

**Reproduction**

1. Start a Local task from an existing folder, with no repository.
2. Wait until the agent is idle and the environment is ready.
3. Open Files → + → Add repositories or folders.
4. Add a folder and select Inside kandev/.
5. Submit, then inspect Files and reload the page.
6. Repeat with a Local Git repository, or a saved repository in a scratch task.

**Observed:** The dialog closes after HTTP 200. The database contains the source records, but the sources do not exist beneath the workspace.
The response contains `session_ids: null` and `workspace_path: ""`.
The Local workspace still contains only `existing.txt`. The scratch workspace has no requested `kandev/` destination.
Both environments have status `ready`, an idle session, and an empty `task_dir_name`.

**Expected:** A successful attachment creates the sources beneath the established root and updates the active session inventory.
An unavailable environment must produce a visible error instead of false success.
This violates AC-TASKS-ATTACH-WORKSPACE-SOURCES-006.1 and 006.3.

**Cause:** `apps/backend/internal/backendapp/workspace_source_materializer.go:129` treats every host environment with an empty `TaskDirName` as unprovisioned.
It returns an empty successful result before reaching the Local-root materializer.
The runtime log explicitly records deferred materialization for these ready environments.

Evidence: [persisted records and filesystem state](qa-2026-10-09/local-materialization-evidence.json),
[Files after successful requests and reload](qa-2026-10-09/local-success-missing-sources.png).

### F2. P1 blocker: Folder attachment silently changes a Worktree workspace root

**Reproduction**

1. Start a single-repository Worktree task with an explicit `main` base branch.
2. Add a saved repository using Inside kandev/.
3. Confirm that the original repository remains the workspace root.
4. Reopen the attachment dialog and add only a folder.
5. Read the continuity note, then submit.

**Observed:** The dialog states, “Working directory, agent session, and running processes stay unchanged.”
It offers no placement control or expansion warning for this folder-only batch.
Submission changes the environment and session workspace from `<task>/E2E-Repo` to `<task>`.
The folder link appears beside `E2E-Repo`, outside the previously established root.
The Kandev session ID remains the same. This check does not establish native-provider continuity.

**Expected:** The current root stays unchanged unless the user explicitly selects an available expansion flow.
The saved placement package keeps expansion blocked pending its separate recovery contract.
At minimum, the dialog must accurately describe the operation it performs.

**Cause:** Worktree folder rows bypass placement eligibility in `use-workspace-source-placement.ts:86`.
In `workspace_source_materializer.go:286`, a batch without explicit placement resolves to the parent task root.
The UI derives its restart warning only from an explicit `expand_root` selection.

Evidence: [dialog before submission](qa-2026-10-09/desktop-dark-folder.png),
[before and after root values](qa-2026-10-09/folder-root-change-evidence.json),
[workspace after attachment](qa-2026-10-09/worktree-root-changed.png).

### F3. P2: Local Git rows remove the promised placement choices

**Reproduction**

1. Open the attachment dialog in an idle Local-folder task.
2. Add a Local Git repository, select its folder, and enter `main`.
3. Compare the form with a saved-repository or folder-only selection.

**Observed:** The valid Local Git row has no Source location section or destination preview.
Users cannot choose grouping under `kandev/`.
The eligibility condition also excludes mixed batches that contain a Local Git row.

**Expected:** Local-folder and scratch tasks offer direct-child or `kandev/` placement for supported source batches.
This is AC-TASKS-ATTACH-WORKSPACE-SOURCES-006.2.

**Cause:** `apps/web/components/task/add-workspace-sources/use-workspace-source-placement.ts:83` requires repository IDs and excludes `localPath` and `remoteUrl`.
The backend preview also requires existing repository IDs in `workspace_source_placement.go:464`.
The Local Git case was reproduced in the browser. The remote-URL exclusion is a source-level observation.

Evidence: [valid Local Git row without placement](qa-2026-10-09/desktop-local-repository-no-placement.png).

### F4. P2: Explicit placement rejects tasks with an empty stored base branch

**Precondition:** The existing task repository has empty `base_branch` and `checkout_branch` values.
The fixture reproduced this through the supported task API by omitting branch fields. Its runtime checkout was on `main`.

**Reproduction**

1. Open that Worktree task's attachment dialog.
2. Select a different saved repository and its `main` branch.
3. Select Inside kandev/ and wait for a valid preview.
4. Submit.

**Observed:** The preview succeeds and enables submission. Submission returns HTTP 400:

```text
invalid workspace repository placement: placement cannot be combined with branch updates
```

The user did not request a branch update.
The same flow succeeds in a fresh control task whose initial repository explicitly stores `base_branch: "main"`.

**Cause:** `service_workspace_sources.go:301` derives the missing legacy branch and adds a repository update.
`workspace_source_placement.go:133` rejects every batch containing such an update.

**Expected:** Safe legacy branch normalization must coexist with new-source placement, or preview must explain the restriction before submission.

Evidence: [valid placement preview followed by the branch-update error](qa-2026-10-09/desktop-placement-branch-error.png).

### F5. P2: Folder rows omit the live-link explanation

**Reproduction:** Select a folder in either the desktop dialog or phone drawer, then read all form text before submission.

**Observed:** The form names the folder and promises session continuity. It does not explain that the attachment is a live link.
It omits the fact that edits affect the original folder and that provider access rules can restrict the target.
The Worktree check confirmed that successful attachment creates a symlink to the original fixture folder.

**Expected:** Present these consequences beside folder selection, distinct from Upload folder.
This is required by AC-TASKS-ATTACH-WORKSPACE-SOURCES-006.2 and 006.6.

Relevant source: `workspace-source-form.tsx:218` and `workspace-change-consequences.tsx:6`.

Evidence: [desktop folder form](qa-2026-10-09/desktop-folder-placement.png),
[phone mixed-source form](qa-2026-10-09/phone-mixed-sources.png).

### F6. P3 suggestion: Desktop controls use inconsistent heights

At 1440px with a fine pointer, Add repository and Add folder measure 36px.
The folder picker and text field measure 28px. Remove, Cancel, and Add to workspace measure 44px.
The shared desktop control contract specifies 28px for ordinary controls, with touch sizing scoped to coarse pointers or phones.

The dialog remains usable, but mixed heights make it less consistent with adjacent desktop forms.
Relevant source: `repository-source-menu.tsx:54`, `workspace-source-form.tsx:141`, and `add-workspace-sources-dialog.tsx:280`.

Evidence: [desktop form](qa-2026-10-09/desktop-folder-placement.png).
