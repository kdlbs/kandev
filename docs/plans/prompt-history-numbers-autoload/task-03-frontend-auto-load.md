# Task 03: Frontend auto-load sentinel

## Acceptance

- The transcript's `useLazyLoadSentinel` moves to a shared hook `apps/web/hooks/use-lazy-load-sentinel.ts` with an options object: `rootMargin` and `rearmWhileIntersecting` (both defaulting to the transcript's current behavior, with `rearmWhileIntersecting: false`). `message-list-native-scroll.ts` delegates to it and the transcript's behavior is byte-for-byte unchanged (same callback-ref bridging, stateRef, observer lifecycle, and no automatic re-arm). Existing `message-list-native.test.tsx` / `message-list-shared.test.tsx` still pass.
- The prompt-history panel auto-loads the next older page when the user scrolls down and the last rendered prompt is not the session's first prompt: a sentinel element after the last row is observed against the panel with `rootMargin: "0px 0px 200px 0px"`, and intersection triggers `loadMore` when `hasMore && !blocked && (!isLoadingMore || joinInFlightWhileLoading)`, where `blocked` is the hard initial/refetch loading flag (`messagesLoading`) and `isLoadingMore` is the older-page in-flight flag. The panel passes the option set `{ rootMargin: "0px 0px 200px 0px", rearmWhileIntersecting: true, joinInFlightWhileLoading: true }`: re-arm must be explicitly enabled (the hook default is `rearmWhileIntersecting: false`, the transcript's no-automatic-re-arm behavior), so after a positive load the sentinel re-observes and auto-loads the next page while still inside the margin instead of stalling until a scroll-away/scroll-back. `blocked=true` never fires and never joins: a refetch is not a cursor request, and the coordinator dedups per `(sessionId, cursor)`, so firing during refetch issues a new older-page request that races the refetch merge. `joinInFlightWhileLoading` bypasses only the `isLoadingMore` term — it never bypasses `blocked`. The sentinel is rendered only while `hasMore && !entries.some((entry) => entry.promptNumber === 1)`; if ordinals are absent it falls back to `hasMore` exhaustion. The panel re-arms only after `loadMore()` resolves with a positive fetched count and the sentinel remains intersecting; the shared `loadMore` checks the per-session in-flight map before local loading guards, so a panel callback during transcript loading or automatic transcript backfill joins the existing promise. A zero-result or rejected load does not re-arm, preventing an automatic retry loop on pagination errors.
- All older-message consumers, including `autoBackfillUntilUserMessage`/`message-backfill.ts`, use the same per-session coordinator and `isLoadingMore` metadata. A backfill page and a panel/transcript page cannot issue duplicate requests for one cursor or clear another consumer's loading state mid-flight. Backfill's existing `MAX_AUTO_BACKFILL_PAGES * BACKFILL_PAGE_LIMIT` becomes a message budget; it computes the permitted page count from the actual first-request-wins page size, so a 20-row winner still reaches the same maximum message depth as a 100-row winner.
- `useSessionMessages(sessionId)` supplies `messagesLoading` from its `isLoading` return (initial/refetch loading, excluding the dedicated `isLoadingMore` field); `useLazyLoadMessages` supplies only older-page state (`isLoadingMore`). If the current message page contains no user prompts but `hasMore` is true, the panel remains paginatable and shows the loading/sentinel state rather than the definitive empty state. If `entries` is empty and `messagesLoading` is true, it shows a neutral initial loading state even when metadata has not yet established `hasMore`; the definitive empty state is rendered only when `entries` is empty, `hasMore` is false, and `messagesLoading` is false.

  ```ts
  export function useLazyLoadSentinel(
    scrollRef: React.RefObject<HTMLDivElement | null>,
    hasMore: boolean,
    blocked: boolean, // hard block: initial/refetch loading (messagesLoading); never fires, never joins
    isLoadingMore: boolean, // older-page request in flight; fires only when joinInFlightWhileLoading is true
    loadMore: () => Promise<number>,
    options?: { rootMargin?: string; rearmWhileIntersecting?: boolean; joinInFlightWhileLoading?: boolean },
  ): {
    sentinelRef: (node: HTMLDivElement | null) => void;
    onUserGesture: () => void;
  }
  ```
- The default options preserve transcript semantics. For panel re-arm, explicitly `unobserve` the current sentinel before awaiting `loadMore()`, then re-observe it only after a positive result and only when the hook is still mounted, the observer identity is current, and the sentinel node is still current. After a rejected or zero-result load, re-observe the node disarmed: ignore the current intersection, arm only after an observed `isIntersecting=false`, and allow a retry on the next true transition. `onUserGesture` provides the panel's wheel/touch retry path when short content prevents a false transition; it retries only while disarmed, intersecting, and eligible, and never retries the same failure automatically. Stale session/root/unmount completions are ignored.
