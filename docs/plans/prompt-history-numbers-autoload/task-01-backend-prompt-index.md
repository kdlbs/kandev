# Task 01: Backend prompt_index contract

## Acceptance

- The message JSON (`v1.Message`) carries an optional `prompt_index` on user messages: the 1-based ordinal of the message among ALL user messages of its own session, ordered by `created_at` ascending with ties broken by `id` ascending. Non-user messages return zero internally and omit the JSON field.
- `models.Message.ToAPI()` copies the field; `v1.Message` marshals it only when `> 0` (`json:"prompt_index,omitempty"`).
- Use a separate 13-column `scanPromptIndexedMessageRows` for `ListMessagesPaginated` (`buildListMessagesQuery`), plus a dedicated `GetMessageWithPromptIndex` 13-column read used only by the idempotent WS replay/response path. Keep hot-path `GetMessage` and full `ListMessages` on their existing 12-column scans; keep the existing 12-column `scanMessageRows`/projections unchanged for `SearchMessages`, `ListMessagesByTurnID`, `ListMessagesForPlugin`, `getMessageByMetadataField`, `FindMessageByPendingID`, `resolveMessageCursor`, and every clarification path. `ListMessagesPaginated` projects the persisted `prompt_seq` column directly (no window pass) and applies the cursor predicate and `LIMIT (limit+1)` to the same normalized-microsecond key. `GetMessageWithPromptIndex` reads the same persisted column, so live, replay, and read ordinal from a correlated COUNT over user rows using the same normalized-microsecond predicate as the live-create transaction (one definition, no window, and no single-row filter trap by construction). The outer cursor predicate and ORDER BY use the SAME `normalized_microsecond(created_at), id` key as the window — never raw `created_at` — so every page is contiguous in ordinal order and the sentinel `promptNumber === 1` stop can never skip a higher-ordinal prompt sharing a microsecond. The cursor bound must be normalized to the exact byte form `YYYY-MM-DD HH:MM:SS.ffffff` (space separator, zero-padded 6-digit fraction, no `Z`, UTC) and bound as that STRING: `resolveMessageCursor` stays on the unchanged 12-column `GetMessage`, and the caller derives the bound by SELECTing `normalized_microsecond(created_at)` for the cursor row through the same SQL expression — never by formatting the driver-parsed Go `time.Time`, whose offset parsing could diverge from `datetime()` for `±TZ` legacy rows. The bound must never be a Go `time.Time` — mattn/go-sqlite3 serializes `time.Time` as RFC3339Nano (`T` separator, trailing `Z`), which mis-compares lexicographically against the space-separated per-row expression and silently shifts page boundaries; PostgreSQL casts the same literal to `timestamp`. The ordered CTE computes the window over the FULL session with NO limit; `LIMIT (limit+1)` applies only in the outer SELECT after the window aggregate, so `prompt_index` stays absolute rather than page-relative.
- The ordinal projection reads the persisted `prompt_seq` column: `CASE WHEN author_type = 'user' THEN prompt_seq ELSE 0 END AS prompt_index`, returning zero for non-user rows. `prompt_seq` is allocated from a per-session monotonic sequence counter inside the create boundary, so ordinals are stable across message deletion and clock corrections.
- A freshly created user message (`CreateMessage` / fresh user `CreateMessageWithID` via `CreateMessageIdempotent`) returns with its `PromptIndex` populated by the repository's atomic per-session create boundary, and the `message.added` event it publishes carries that final index. Live-create ordinals are allocated from the session's durable sequence counter inside the atomic boundary, so live, replay, and read ordinals agree by construction. Idempotent replay uses `GetMessageWithPromptIndex` and returns the existing indexed row without a duplicate add event. User `message.updated` events from `UpdateMessage` re-read the affected user row through `GetMessageWithPromptIndex` before publishing, so they carry the stable index; agent messages and streaming agent content/thinking updates stay on hot 12-column reads and never carry the field.
- Additive migration: `task_session_messages.prompt_seq INTEGER NOT NULL DEFAULT 0`, a `task_session_prompt_seq(task_session_id PRIMARY KEY, last_seq)` counter table, and an idempotent backfill that assigns existing user rows their previously derived ordinal and seeds each session's counter at its maximum. The additive expression index `(task_session_id, normalized_microsecond(created_at), id)` (SQLite and PostgreSQL) serves the outer cursor predicate and ORDER BY; the dialect helper is the single source that builds both the query expression and the index DDL. Failed create attempts do not mutate retry-visible `CreatedAt` or `PromptIndex` fields.

- `apps/backend/internal/db/dialect/` — add the dialect-specific normalized-microsecond timestamp expression used by the window `ORDER BY`, the outer cursor predicate, outer ordering, and the single-row count predicate. PostgreSQL's `timestamp` column already stores UTC microseconds, so the helper is an identity/cast there. SQLite stores the value as text via mattn/go-sqlite3 (`YYYY-MM-DD HH:MM:SS.fffffffff±TZ`); the helper must normalize any embedded `±TZ` offset to UTC before deriving the key: pass the FULL stored string (wall clock + fraction + offset suffix) through `datetime()`, which parses the offset and converts to UTC at second precision, and carry the fractional digits separately (zero-padded to 9, truncated to 6), concatenated to a `YYYY-MM-DD HH:MM:SS.ffffff` text key. `datetime()`/`strftime('%f')` drop sub-second precision, so the fraction must be handled independently; `strftime('%f')` yields only milliseconds and `julianday` lacks float precision for microseconds, so neither may serve as the key. UTC-written rows make the offset conversion a no-op, but the expression must still handle non-zero offsets from harness seeds and legacy rows so SQLite, Postgres, and the frontend UTC key agree.

Summary: `v1.Message` / `models.Message` carry `prompt_index` (omitempty, zero for non-user rows); `ToAPI` copies it. Repository: new 13-column `scanPromptIndexedMessageRows` for `ListMessagesPaginated` (direct `prompt_seq` projection, cursor predicate and `LIMIT (limit+1)` on the normalized-microsecond key), dedicated `GetMessageWithPromptIndex` (persisted `prompt_seq`), cursor bound derived via the SQL `normalized_microsecond` expression (`messageCursorKey`), and an atomic per-session create boundary for user messages (`createUserMessageWithBoundary`): the ordinal is allocated from the durable per-session sequence counter (`task_session_prompt_seq`), live zero-timestamp creates clamp a colliding/backward ordering key forward by one microsecond tick (no lead window — a backward clock never blocks), explicit timestamps must be strictly after the session's newest user message (`ErrMessageTimestampNotAfterNewest`), and failed attempts restore caller-visible `CreatedAt`/`UpdatedAt`/`PromptIndex`. Dialect: `NormalizedMicrosecond` (SQLite `datetime()` UTC normalization with a separate right-padded/truncated fraction digit run; PostgreSQL identity) plus `PromptOrderIndexDDL` for the one additive expression index `(task_session_id, normalized_microsecond(created_at), id)` (`ensurePromptOrderIndex`).
