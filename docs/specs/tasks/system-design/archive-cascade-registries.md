# Archive Cascade Registries

## Authority

This document names the checked-in registries required by the archive cascade.
The registries are implementation artifacts, not prose lists. Work order 01 owns
writer, typed table, provenance, and lifecycle-publisher entries; work order 02
owns config-surface entries; work order 03 owns the startup catalog/runner plus
compensation and runtime reconciliation entries; work order 04 owns the
deterministic declared export and independent verifier. Each owner maintains its
schema and focused tests, while Task 04's verifier compares all artifacts
without importing implementation registries.

## Artifact paths and closed schemas

| Artifact | Owner package | Exact entry schema | Rejection rule |
| --- | --- | --- | --- |
| `apps/backend/internal/task/archivecascade/registry/writers.go` | `archivecascade/registry` | `WriterEntry{Package,OwnerSymbol,FunctionSymbol,Table,Columns,Mutation,AggregateCommand,Classification,Invariant}` | duplicate symbol/table mutation, wildcard/empty columns, missing command, unclassified SQL writer, stale source position, or direct lifecycle publisher fails generation |

| `scripts/verify_archive_cascade_registries.py` | verification tooling | reads compiled/AST/SSA/SQL symbols, vocabulary, and traceability, and in dialect-attestation mode introspects SQLite and PostgreSQL catalogs into canonical `ObservedEntry` values | importing implementation registry data, allowing ignored symbols, missing a requested dialect connection, unresolved traceability, or unequal observed/declared sets exits nonzero |

Each table entry declares every column type/nullability/default/collation, index columns/uniqueness/predicate/collation, check, and foreign key with ordered local columns, referenced table plus ordered referenced columns, `MATCH` (`SIMPLE|FULL|PARTIAL`), `ON DELETE`, `ON UPDATE`, `DEFERRABLE`, and `INITIALLY DEFERRED`. `DialectDDLHash` stores two lowercase hex SHA-256 values keyed by dialect. Each hash covers canonical DDL text for that dialect: statements sorted by table name, identifiers quoted, columns in ordinal order with type/null/default/collation, followed by indexes, checks, and foreign keys in canonical order, serialized as UTF-8 and hashed. Fresh DDL and migrations render from this entry; the verifier compares live columns, constraints, indexes, collations, and FKs to it. No separate DDL list is authoritative. Entries carry integer schema version and sorted canonical order. For `task_archive_operations` plus child `task_archive_operation_scopes` (PK `(operation_id, scope_workspace_id)`), the entries declare the scope-row barrier key and generation/phase invariant; the verifier expands every scope row when checking tier-4 admission.
Private transaction helpers are attributed to every public caller. Exemptions
are explicit entries with invariant, exact columns/effects, and owner; wildcard
or category entries are invalid.

Task 04 generates `declared.json` after Tasks 01-03 with
`go run ./internal/task/archivecascade/registry/export --output internal/task/archivecascade/registry/declared.json`.
The exporter uses repository root as the invocation root and this fixed,
`apps/backend/internal/task/archivecascade/registry/writers.go`,
`apps/backend/internal/task/archivecascade/registry/tables.go`,
`apps/backend/internal/task/archivecascade/provenance_registry.go`,
`apps/backend/internal/task/archivecascade/registry/export/main.go`,
`apps/backend/internal/workspaceconfig/registry.go`,
`apps/backend/internal/backendapp/startup_registry.go`,
`docs/specs/tasks/system-design/archive-cascade-vocabulary.yaml`, and
`docs/specs/tasks/system-design/archive-cascade-traceability.yaml`. It requires
each path to be a regular UTF-8 file with no symlink, reads exact bytes, and
excludes `declared.json`, build output, timestamps, environment, and absolute
paths.
For schema version `1`, each file contributes
`sha256(exact_bytes)`; `source_sha256` is SHA-256 of the UTF-8 RFC 8785 bytes of
`{"schema_version":1,"files":[{"path":repo_relative_path,"sha256":...},...]}`,
with files sorted by path and no omitted/extra manifest member. The top-level
artifact arrays are sorted by these keys: writers
`Package,OwnerSymbol,FunctionSymbol,Table,Mutation`; tables
`Name,Classification,OwnerSelector,LockTier,Ordinal`; provenance
`SourceID,Variant,Constructor,Caller`; config `OwnerSymbol,FunctionSymbol`; and
startup `Stage,ID,OwnerSymbol,StartSymbol`. Re-running unchanged inputs is
byte-identical; CI and Task 04 recompute the digest and reject stale output.

`writers.go` contains every insert/update/delete of task, task environment,
session, runtime, group, cleanup, marker, revision, parent-mutation-result,
detach-mutation-result, outbox, workspace, config claim, integration, secret,
diagnostic, audit, creation-step, release, and provenance rows. `Mutation` is
one of `insert|update|delete|claim|publish` and `Classification` is one of
`aggregate|retained|workspace_delete|aftermath|exemption`.
Lifecycle events may be written only by the aggregate command entry; publisher
entries identify the sole outbox path and reject direct bus publication.

## Config and provenance coverage

`workspaceconfig/registry.go` enumerates every ConfigLoader/FileWriter/memory/Git/
Office sync/default/settings/path-event/delete method with exact read/write/git/
delete access and fence capability. `provenance_registry.go` enumerates HTTP,
MCP, quick-chat, profile, GitHub, GitLab, Azure, Jira, Linear, Sentry, automation,
plugin, e2e, and workspace-delete callers. Its canonical fields point to the
closed SourceID object and trusted row/context; delayed jobs persist the exact
bytes, and tree children copy them. Creation compensation entries point to
handle-bound Abort, never DeleteTask.
Each listed category expands to concrete owner/caller symbols; category-only or
wildcard provenance entries are invalid. Office workspace deletion is explicit:
`office/workspaces.Handler.deleteWorkspace` -> `office/service.Service.DeleteWorkspace`,
`task/handlers.WorkspaceHandlers.httpDeleteWorkspace` and
`wsDeleteWorkspace` -> `DeleteWorkspaceWithConfirmName`. Each entry binds
`workspace_id`, `confirm_name`, authenticated `UserActor{UserID,RequestID,AuthMode,Synthetic}`,
resolver evidence, operation ID, and delayed-job bytes; `TestOfficeWorkspaceDeleteActorRace`
rejects stale actor/confirmation/workspace resolution before Store mutation. Office
runtime root/subtask and authenticated `agentctl taskCreate` routes remain in the
creation matrix.
## Independent verification

Task 04 runs from `apps/backend`:
`python3 ../../scripts/verify_archive_cascade_registries.py --production
--compare internal/task/archivecascade/registry/declared.json`.
The verifier first checks the declared export schema, `source_sha256`, canonical
sort order, and freshness against the owner source files; it then builds observed
sets from production Go AST/SSA, migration SQL, and compiled symbols, never from
registry packages or their tests. It compares writer columns, config
methods/access, provenance callers/constructors, publishers, startup
stage/effect/cleanup/readiness, migration-only aliases, and the exact table
catalog. Fixtures and failpoints are owned by Task 04 and use independent
names/data; a passing implementation-registry test is not independent evidence.
