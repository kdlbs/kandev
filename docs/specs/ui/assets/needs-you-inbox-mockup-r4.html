Which tab control, and why it is not the default one

A design call I can make from the shipped component rather than from taste. packages/ui/src/tabs.tsx has two variants. The Office inbox uses default. On the dark theme that variant's selected state resolves to the track colour it sits on: bg-muted is #2a2a2a, and the active trigger paints dark:bg-input/30 over it — --input is also #2a2a2a, so 30% of #2a2a2a on #2a2a2a is #2a2a2a. The active border is --input, the same colour again. Selection is carried by the label's brightness alone.

10

The rules this mockup encodes

Lift these into the card as acceptance criteria; each one is a decision the drawings already make.

  1. Entry gate, not a state filter. A row enters only if it carries an action you can take now. "Not Running" is 275 rows at a 100% false-positive rate; the gate is 0.
  2. The badge counts decisions you owe, and nothing else. Never the queue size, never the history tab, never failures. It must be drivable to zero, and badge > 0 already means a zero renders nothing.
  3. One read path. Badge and list both read the clarification-bundle path. Two shipped resolvers disagree today; pick one for both consumers.
  4. Answering happens in the row. A display-only inbox still makes you jump around, from a tidier list. Answer and resume posts the answer and restarts the session in place.
  5. An empty inbox names what it is not counting. Never "all caught up" alone.
  6. History is read-only. No Re-ask: five of nine push-blocked questions had already settled themselves. Permissions appear here, labelled, and never in the badge.
  7. Dismiss and snooze are a per-user sidecar and never mutate the queue — Paperclip's rule, adopted verbatim.
  8. An agent may only name itself as the owner of a row it creates. 430 of 430 questions in the last ten days were agent-authored and Kandev has no equivalent gate. Paperclip enforces this one against its own agents — I had it returned to me as a 403 while trying to hand you a row.
  9. Workspace-scoped. Other workspaces contribute a count in the empty state and the switcher, never a row.
  10. Reuse the board's colour vocabulary. Yellow is a question, amber is a permission, red is a failure, emerald is running, violet is background work. The Inbox introduces no new hue.
