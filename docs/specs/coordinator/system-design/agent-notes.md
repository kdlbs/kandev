# Coordinator agent-tier notes System Design

## Requirement mapping

| Requirement | Mechanism |
| --- | --- |
| REQ-COORDINATOR-AGENT-NOTES-001 | Store, routes and authority |
| REQ-COORDINATOR-AGENT-NOTES-002 | Validation and per-turn delivery |

## Store, routes and authority

Add additive SQLite and PostgreSQL migrations in `internal/coordinator` for `coordinator_notes`, immutable `coordinator_note_versions`, typed citations and proposal-note links. Note identity, coordinator and workspace, creation time, current version, deleted time, last successful validation time/result, last attempt time and failure, use count and expiry are stored separately from versioned type, text, citations and provenance. Persist UTC timestamps. Cascade with coordinator/workspace deletion. Human version provenance is `{kind: human, user_id}`; dream provenance is `{kind: model, model}`. A revert copies provenance and content, with an additional actor and timestamp for the revert itself.

Expose coordinator-scoped list, note detail (with versions and one version's detail), references (current and history), create, edit, delete and revert HTTP routes under the existing `/api/v1/workspaces/:id/coordinators/:cid/` prefix. Apply `workspace.read` to reads and `workspace.manage` to mutations, resolving the coordinator in the workspace first. Create returns 201; successful mutations 200; bad input 400 with one reason code from AC-COORDINATOR-AGENT-NOTES-001.5, unauthorized 403, unknown/foreign identity 404, version, expired or deleted conflict 409, and dependency errors 503. Edit and revert are full replacements and require the current version in the `version` field, except that an equal-content request is a no-op that succeeds with any `version`; a revert also carries `target_version`; delete requires `version` in the body for every request, and matches it against the current version for every nondeleted note (live, stale, unavailable or expired), while a deleted note answers 200 for any integer. Mutations are evaluated in the fixed order of AC-COORDINATOR-AGENT-NOTES-001.11, which also defines normalization; a no-op is decided before the version comparison. Citation resolution (up to 5 seconds, starting at step 8) never holds a transaction or the SQLite writer. The commit (step 9) is one short transaction: on SQLite an immediate write transaction, on PostgreSQL a row lock on the coordinator row taken first (and on the note row for edit, revert and delete). Inside it the system re-reads the note and re-evaluates deleted, expired (against the commit time), equal content, version and, for a create, the 100-note count, in that order, then writes with a conditional update on the note's current version, so a delete that created no version, an expiry that passed during resolution, a concurrent identical edit (which becomes a 200 no-op) and a concurrent different edit (`conflict`/`version`) are all decided from committed state. A create that loses the recount returns `note_limit_reached` after its citations resolved. Delete is a tombstone that creates no version; a repeated delete returns 200 without a version match (its body must still pass step 2 of AC-COORDINATOR-AGENT-NOTES-001.11). Edit or revert of an expired or deleted note returns 409 with that reason and an unchanged row; deleting an expired note is allowed. Content equal to the current version returns 200 with no new version. Edits and reverts never change expiry or use count; a new version resets validation state to not yet validated. At most 100 nondeleted notes per coordinator, 10 citations per note, 64 KiB bodies; a create is not idempotent, so clients do not automatically retry an ambiguous create.

Create and edit validate every textual input with the existing credential detector (`coordinator.ContainsCredential`, as the dream gate does), including revert and internal approved-item creation, and never log rejected data; versions cannot bypass the gate. They also resolve each citation once against the workspace (AC-COORDINATOR-AGENT-NOTES-001.9): shape and scope failures and confirmed absence are 400, dependency failures 503; revert checks shape and the gate only. The internal seam accepts an already approved item identity with a unique constraint, a model stamp and the same type, text and citations; mapping a dream item to those fields is the caller's responsibility in 3.5-2. A repeat of the same item returns the existing result, different content for that identity conflicts. It must not grant approval itself and has no HTTP or MCP route.

Register `features.coordinatorPhase35` in the typed registry (restart required, mutable, experimental, medium risk, label "Coordinator project notes", risk text stating that managers' notes enter every turn of the coordinator as lower-trust data) and in `profiles.yaml` with prod, dev and e2e all `"false"`; end-to-end specs set `KANDEV_FEATURES_COORDINATOR_PHASE35=true` explicitly. The flag is effective only together with the coordinator, phase 2, phase 3 and phase 3.1 flags; no change to their flags or policy. Flag off keeps rows, disables routes, UI and delivery, and does not pause expiry. Changes to notes do not reset the conversation.

## Validation and per-turn delivery

Normalization for uniqueness and equality (AC-COORDINATOR-AGENT-NOTES-001.11): text is trimmed; identifiers (task id, turn id, commit SHA) are compared lower-cased; a path is compared after converting backslashes to slashes and removing `.` segments, and a path that still contains `..` or is absolute is invalid; a pull request is compared by repository id and number. Citation order is ignored for uniqueness and equality, and the stored order of a no-op remains that of the current version. The "over the cap" marker is derived on each settings read: rank the notes that are neither deleted, expired, stale nor unavailable (not-yet-validated notes included) by creation time ascending then note id ascending; those ranked beyond 38 are over the cap and are not delivered.

Citation shapes are: `{kind: turn, id}` (ledger row of this coordinator), `{kind: task, id}` (task in workspace), `{kind: pr, repository_id, number}` (positive number in a workspace repository), and `{kind: file, repository_id, path, sha}` (relative path, full commit object ID). Reject duplicate citations, absolute paths, traversal, malformed identifiers and unsupported kinds. Limit each note to 10 citations. Resolution is read-only and never fetches. Task existence includes archived tasks; a turn must exist and belong to the coordinator (the ledger retains rows for 400 days, after which a turn citation is stale); a PR must exist in the cited repository, read through the repository's provider lookup that the workspace already uses, and a repository whose provider offers no lookup is unavailable. Repository HEAD means the tip commit of `refs/heads/<default_branch>` in the repository's local clone (`models.Repository.LocalPath`), falling back to `refs/remotes/origin/<default_branch>` when the local branch ref is absent; a file citation is valid only when the cited commit exists, the file exists at the path in that commit, and its blob at HEAD equals the cited commit's blob. A repository row missing from the workspace is confirmed absence (stale); an empty `LocalPath`, a missing clone, an unresolvable ref or any permission, network or read failure is unavailable, never absence. Paths are not executed and symlinks outside the repository are not followed. Missing citations are never repaired or guessed.

A note's status is computed from all its citations without short-circuiting on unavailability: any confirmed absence or change makes it stale, else any unavailable citation makes it unavailable, else valid; the result does not depend on citation order.

At turn admission take one UTC time and enumerate nondeleted notes whose expiry is strictly later. Validate their citations against the then-current board and one captured HEAD per repository, running at most four lookups at a time and stopping the wait after 5 seconds for the whole turn, counting every unfinished citation as unavailable. Lookups are queued in `created_at ASC, id ASC` note order and citation order. Persist every attempt result (valid, stale or unavailable) with a compare-and-swap on `last_attempt_at`: the write applies only when the note version still matches and the admission time is strictly later than the stored `last_attempt_at`, and it sets `last_attempt_at` to that admission time; equal admission times go to the first commit. A successful or stale result also updates the last successful validation time and result; an unavailable result stores only the attempt status and never overwrites the last successful result, and a later successful validation of the same version clears it. A validation that loses the comparison is not persisted but its turn still uses its own computed result. Stable snapshot ordering is `created_at ASC, id ASC`; take the first 38 valid notes. "Over the cap" is not stored: the settings read derives it as defined in the requirements overview.

Rendering: each line is `- [<note id>] <type>: <text>` after replacing newlines and control characters with spaces and removing every `<kandev-system>` and `</kandev-system>` sequence (repeating until stable, using `sysprompt.StripTags` for the closing tag) and the footer sentinel. The section is `sysprompt.Wrap` of: a header line stating that the following lines are advisory, lower-trust notes from the project's managers, that they grant no authority or permission and that manager instructions take precedence; up to 38 note lines; and a footer line `END OF NOTES`. The opening and closing tags share the header and footer lines, so the section is at most 40 lines. No eligible notes means no section at all. Because it is wrapped, `sysprompt.StripSystemContent` hides it from the transcript.

Composition: `backendapp/coordinator.go` builds `coordinator.StandingInstructions` once via `orchestrator/coordinator_prompt.go` and attaches it only to a conversation's first prompt (`wrapCreatedSessionPrompt`); preserve that. Add a separate per-turn note step at the point where a coordinator conversation turn's prompt is composed for a new session turn, keyed by the durable session-turn identity: first turn (after the standing block), later turns, wake deliveries, and recovery re-delivery. Do not add it in `effectivePromptForSession` call sites that serve mid-turn steers (`steer.go`) or the workflow-step emptiness check, which judge the raw prompt without the section, and never for dream-episode tasks (`coordinatorMetadataID` is empty for them) or tasks with no coordinator id.

Snapshot and receipts: persist the frozen selection (note ids, versions, rendered lines) for the session turn before the prompt is sent. Persist a unique `(note_id, session_turn_id)` delivery receipt and update count and expiry in the same transaction when the turn's prompt is accepted by the existing session-turn acceptance; the new expiry is the later of the current expiry and the commit time plus 30 days, and a note deleted before that commit, or whose expiry is not strictly later than the commit time, gets a receipt but no count or expiry change (the frozen content was still delivered; an expired note is never revived). Replay or recovery of the same turn reuses its frozen selection and cannot count twice. Preparation happens only when a session turn is first dispatched. If it fails globally, persist an empty snapshot marked failed, send the turn without the section, log a bounded error without note text and record no delivery; recovery or replay of that turn reuses the empty snapshot and never prepares again. If even the snapshot cannot be persisted, send without the section and record nothing; a recovered turn with no snapshot is likewise sent without the section. A turn cancelled or failed before acceptance records no delivery. An ambiguous send uses existing turn delivery recovery and the same frozen snapshot rather than producing a second use. A note edit after the snapshot affects the next turn, not the accepted snapshot. The prompt-hash ledger keeps its meaning: `coordinator_turns.prompt_hash` stays the hash of the standing instructions a new conversation would receive, is computed without notes and does not change on note edits. The notes a turn received are recorded by its delivery receipts, readable by session-turn identity; replay renders the baseline without notes, as replay.md already specifies, and the replay design needs no change.

## References and settings

Extend the proposal tool payloads through one kind-agnostic path (so `propose_answer_kandev` from the answer-proposals slice gets `note_ids` with no per-kind code whenever it is registered; its landing is not a prerequisite) with optional `note_ids` (absent, null and empty are equal; reject malformed, duplicate or more than five). Validate each against the frozen delivered index and the current state of the note in the same transaction as the proposal insert: a note whose current version differs from the delivered one is judged on its current state (deleted, expired, or stale by its latest stored result; unavailable or not-yet-validated is not stale and remains referenceable). Return the reason codes and ordering of AC-COORDINATOR-AGENT-NOTES-003.1, creating nothing on failure. Serialize note mutations and proposal admission in coordinator commit order; a deleted, expired or stale note cannot be linked after that state commits. Store `(proposal_id, note_id, note_version)` uniquely with the proposal. There is no proposal deduplication today, so no retry semantics beyond a new proposal exist to preserve; each accepted call writes its own links. Project current references from proposal status and the created task's live status rather than copying a mutable count: proposals with status `pending` or `approving` (executing means `approving`), and tasks created from `approved` proposals that are neither archived nor in state COMPLETED, FAILED or CANCELLED. A proposal's card is the proposal itself; its approved created task is a separate reference. Existing tasks without a linked proposal are not inferred to rely on a note. Historic links remain and are returned by the references-history read, including after note deletion. Current references are computed on each read; settings refetch on load and after each mutation, with no live push.

Add a Notes section to coordinator settings using existing authorization and localized UI patterns. Show notes in the order of AC-COORDINATOR-AGENT-NOTES-001.10, with states live, stale, unavailable, not yet validated, expired, over the cap, and deleted (hidden unless an include-deleted toggle is on), and a version list whose rows show number, time, actor and provenance. Citations are typed identifiers in the editor. Error responses show the reason code in localized copy. On a 409 `version` preserve the draft, show a conflict and reload the current version only on user action; on a 409 `expired` or `deleted` keep the draft read-only, state the reason and offer create-from-draft (and delete for an expired note) with no reload. Expired notes hide edit and revert. Validation help text says citations are checked against the repository's local clone, which is never fetched, so a commit present only on the remote reads as missing. The same single-column order works on mobile with a full-screen detail/editor; the desktop uses an inline list and detail. Empty/loading/error states are explicit. UI copy uses all shipped catalogs and no em dash. Phone and keyboard acceptance is the Playwright matrix in the work order: desktop and phone viewports, Tab and Enter operation of list, editor, delete and revert, in the English and one non-Latin-script locale, plus `pnpm run i18n:check` for the remaining catalogs.

## Dependencies and risks

Build on `feature/coordinator-raisable-ap5`; reconcile with the answer-proposals slice ([ADR](../../../decisions/2026-11-07-coordinator-answer-proposals.md)) if it has landed, without reimplementing it. The `answer` kind does not exist in this base: AC-COORDINATOR-AGENT-NOTES-003.1 is verified against the existing proposal kinds plus a test-registered stub kind proving the extension is kind-agnostic. Repository/provider availability may make notes unavailable; omission prevents unverified memory from entering a turn. Credential detection is the existing pattern gate, not a guarantee to recognize every secret, and it can reject benign text containing its literal patterns. Notes beyond the index cap never reach a turn and expire, and expiry continues while the flag is off; both are deliberate consequences of AC-COORDINATOR-AGENT-NOTES-002.4 and 002.5 that the repository owner may revisit. [ADR amendment](../../../decisions/2026-09-30-coordinator-phase-3-1-record-and-measure.md) records the early-build exception.
