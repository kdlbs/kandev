# Sandbox macOS support requirements

## Overview

Extends [Sandbox policy requirements](sandbox-policies.md), which own every behavior not restated here. Its terms apply. [Design](../system-design/sandbox-macos-support.md). Provider-side requirements: [REQ-PLUGINS-SANDBOX-002](../../plugins/requirements/sandbox-provider-capability.md).

### REQ-AGENTS-SANDBOX-011: macOS Local and Worktree support

**Intent:** Operators on Apple Silicon hosts can confine Local and Worktree agents with the same policies, and the product states exactly where macOS confinement differs from Linux.

- **AC-AGENTS-SANDBOX-011.1:** Agentctl on darwin shall advertise `sandbox-launch.v1` only when a startup probe proved that Seatbelt confinement works on that host. Absent means unsupported; there is no pending or unknown state.
  Agentctl runs the probe once, before it serves any request, with a 5-second bound. The probe creates two files in a fresh directory, runs an unsandboxed control read of the second file, then runs a trivial reader under `/usr/bin/sandbox-exec` (absolute path, never `PATH`) with a deny-default profile that grants only the first file plus the minimum the reader needs to start. It passes only when the control read succeeds, the sandboxed read of the first file succeeds, and the sandboxed read of the second file fails with the operating system's permission error.
  The probe deletes its directory and kills its child on every outcome, and logs its failing step. The result is immutable; restarting agentctl is the remedy. The capability is never advertised on error, timeout, or a panic in the probe.
  The probe checks no provider binary. The provider's pinned runtime is verified by core for every attempt and by the Settings availability check, as on Linux.
- **AC-AGENTS-SANDBOX-011.2:** The launch path shall admit a required sandbox on a Local or Worktree executor on darwin only when that executor's agentctl advertises the capability, and shall otherwise fail before startup with the class `sandbox_host_unsupported`, with no unwrapped retry. The Settings availability check shall apply the same capability test to the backend's own managed local agentctl and report the same class as its blocker.
  There is one reason: the host cannot confine agents. The check runs in `prepareExecution` (`backendapp/sandbox_runtime.go`), after the executor type validation and before the `protectedPorts` and previous-attempt steps and before `sandboxruntime` Prepare, where the transport and the executor's `/identity` are known. It refuses when the `/identity` read fails or the capability is absent. A refusal there happens before provider compilation and before any attempt is captured, so it creates no attempt, no sandbox status and no Execution details. The refusal is the typed Go error carrying the stable code `sandbox_host_unsupported`; the launch surfaces it through the existing generic launch-failure handling, and the code is written to the log and is the Settings availability blocker. No persisted launch cause prefix is promised, and no category, cause code, detail field, or web mapping is added. Task-creation admission (`sandbox_creation.go`) is unchanged and reads no capability. The availability check reads on every call and caches no darwin outcome; its existing bound applies, and an unreadable or timed-out read reports the same blocker. Core sets the attempt's `ownership_scope` to `process_tree` at attempt capture when its own host OS is darwin, never from an executor answer.
  A provider that answers `host_unsupported` for the host (the Nono provider does for darwin/amd64) is refused with the same class when the core host is darwin; the match happens at the provider dispatch, where `ErrSandboxHostUnsupported` wraps `ErrSandboxProviderUnavailable` (design: Host probe and admission). The mapping applies only when the core host is darwin: on every other host a provider answer keeps its existing handling and failure class.
- **AC-AGENTS-SANDBOX-011.3:** On darwin the sandbox shall never grant the user keychain, and no policy, override, or provider option shall bypass keychain protection. Agent credentials shall reach the child only through the policy's environment keys; a key whose value is missing or empty at launch is not effective. An agent whose login lives only in the keychain therefore runs unauthenticated and surfaces its own authentication error. A dedicated failure class for that case is excluded from this version.
- **AC-AGENTS-SANDBOX-011.4:** Every darwin attempt, including the start of a replacement attempt, shall run in a fresh private per-attempt root created by core's existing runtime materialization. Its TMPDIR shall be that root's `tmp` directory, and the sandbox shall grant no read or write access to `/tmp`, `/private/tmp`, `/var/folders`, or `/private/var/folders`.
  The root is owner-only and is removed with the attempt's artifacts only after its owned processes are verified gone. A retry is a new attempt with a new root; no root is reused. Core's runtime materialization is split into a reserve step, which creates the root and owns its removal until materialize commits, and a materialize step that renders into the reserved root; a process-tree attempt reserves before the provider compiles and a failed preparation removes the reserved root. The reserved `tmp` path is passed to the compile as the value of the `sandbox.child.tmp` reference, always on darwin and also when an `agent_state` grant supplies HOME, config, and state. The environment and the profile therefore name the same directory. The early allocation applies to a process-tree attempt only; a kernel-container attempt calls reserve and materialize back to back after compile, in its existing order. Creating the sandbox runtime refuses a managed state root that resolves under any denied path above, with the existing sandbox-runtime-unavailable error; no darwin reason is added for it.
  Git reads no host configuration: the child gets `GIT_CONFIG_NOSYSTEM=1`, its HOME is the isolated one, and the real `~/.gitconfig` is never granted. A commit therefore fails with git's own identity message until the follow-up in Exclusions lands.
- **AC-AGENTS-SANDBOX-011.5:** On darwin, agentctl is the only party that signals sandboxed processes, and ownership is the process group of the wrapper it starts, not a kernel container. The wrapper (the provider's launcher) is started with the existing `Setsid`, so its process ID equals its process group ID and its session ID. The backend never signals, reaps, or terminates a darwin sandboxed process.
  The running owner is reported on the existing owner route (`GET /agent/sandbox/owner`, `ProcessOwner.Supervisor`) and bound by the existing `BindOwner`. On darwin the wrapper is both supervisor and child: the bound child identity is the supervisor identity, no provider session identity is required, and the container membership checks of Linux (`Contains`, `IsDescendant`) are replaced by a group identity test that `BindOwner` adds for a process-tree attempt: `GroupID == SessionID == PID` of the supervisor. No group identifier is stored beyond the existing owner record; the group scanned for verification is the supervisor's process ID. A darwin attempt carries no containment object; agentctl's `ConfigureContainment` is a no-op keyed on the host OS being darwin, never on a nil containment.
  Stop is agentctl's existing process stop: terminate the group after the existing grace, then kill it, with the wrapper reaped only by agentctl's existing exit waiter. No second reaper and no new stop operation exist. After the supervisor has exited, the attempt's `Close` (and `ReconcileAttempt`) verifies the group by a read-only scan of the process table for members whose group ID equals the recorded one, polling every 100 ms for at most 5 seconds, outside the manager lock that serializes Prepare and attempt capture. An empty group verifies termination and files are then removable. A surviving member at the bound, a process-table read error, or a permission error leaves termination unverified: the attempt is `recovery_required` with the existing presentation for missing ownership evidence, its files are retained, replacement stays blocked, and `Close` can be retried. `Close` is idempotent and a second call after verified termination returns the recorded outcome.
  Nothing is re-adopted after an agentctl restart and no stop is attempted for it. Recovery uses the existing `ReconcileAttempt` rule: the attempt stays `recovery_required` while the recorded wrapper identity is not proven exited, and is finalised as stopped only when it is exited and the group scan is empty. A process still running after agentctl was restarted therefore stays unmanaged until the operator stops it; stopping it from the product is excluded from this version. A group ID reused by an unrelated process makes the scan non-empty and fails closed; this residual is declared.
  Execution details shall state the ownership scope as process tree, not kernel container, and shall always state that a process which left the group cannot be tracked. The sandboxed child shall stay in the wrapper's process group; the conformance suite proves it (AC-AGENTS-SANDBOX-011.11).
- **AC-AGENTS-SANDBOX-011.6:** On darwin, approvals are not supported, independent of what the provider description declares. An attempt whose ownership scope is process tree shall create no approval callback listener, callback secret, or pending approval row, and Execution details shall show approvals as not supported on this host. A provider description without an approval wire is admitted on darwin only; Linux keeps refusing it, and no approval declaration, proto field, or approval-kind semantics is added or changed.
  `RecordApproval` shall refuse a request for a process-tree attempt with the existing `ErrIneligible`, writing no row and never waiting for a deadline; the refusal is observed by that error and the absence of any approval row. The decision reads the attempt's private snapshot `ownership_scope`, never a live provider call. No new reason string, response shape, or channel behavior is added. Ordinary agent tool permissions are unaffected, and Linux denial reasons are unchanged.
- **AC-AGENTS-SANDBOX-011.7:** An attempt whose ownership scope is process tree shall have no denial report: core stores no report row, assembles no envelope, never reads the provider's report, and report capture, refresh, and close skip it. A missing report for such an attempt is not an error. Execution details shall state that filesystem denials are unavailable on macOS, chosen by the attempt's `ownership_scope` and never by a report, and shall not say that no denials were observed. With no report there are no records, so the learning review for that attempt offers no proposals. A report assembled from a Seatbelt log reader is excluded from this version.
  No report field, stored report shape, or digest changes; an attempt with no `ownership_scope` reads as `kernel_container` and reports through its provider as before, so Linux text and behavior are unchanged.
- **AC-AGENTS-SANDBOX-011.8:** A darwin sandbox status shall be `active` only under the evidence rule of AC-AGENTS-SANDBOX-008.2. When the provider yields no current status evidence for a running darwin attempt, the status shall be unknown and shall not show an active shield. A darwin attempt reaches `running` when the existing `BindOwner` succeeds with the wrapper identity of AC-AGENTS-SANDBOX-011.5. The other statuses behave as on Linux.
- **AC-AGENTS-SANDBOX-011.9:** Kandev MCP access and network egress on darwin shall use the same topology as Linux: the child can reach only the loopback port of the provider's local proxy and the per-attempt MCP relay port, and the provider's upstream proxy forwards through the exact-host core CONNECT relay. Direct egress and arbitrary loopback ports shall be denied.
- **AC-AGENTS-SANDBOX-011.10:** Linux capability advertisement, supported host set, cgroup ownership, approval declaration and file approval, denial reasons, report behavior, and git handling shall be unchanged by darwin support. Existing Linux tests shall pass unmodified. Persisted records that lack `ownership_scope` shall read as `kernel_container`; the field lives in the private attempt snapshot and is projected read-only into the public execution snapshot with the same default. A present value other than `kernel_container` or `process_tree` fails snapshot validation as an invalid stored attempt; only an absent value defaults.
- **AC-AGENTS-SANDBOX-011.11:** A darwin conformance suite shall run on a real macOS host and record, for each canary, one result of `allowed`, `denied`, `control_failed`, `error`, or `skipped` plus an exit code. It shall never print real file names, file contents, or secret values.
  Each canary is a small helper that performs one operation and exits 0 on success, 10 on a permission error (EPERM or EACCES), and 11 on any other error. Every canary has an unsandboxed control performing the same operation against the same fixture, which must exit 0, with a bound of 10 seconds per run. In the sandbox, exit 0 is `allowed`, exit 10 is `denied`, and exit 11, any other code, a signal, or a timeout is `error`. A control that does not exit 0 is `control_failed`. A deny canary passes only when its control is `allowed` and its sandboxed run is `denied`; an allow canary passes only when both are `allowed`. `control_failed` and `error` fail the suite. A canary whose real target is absent on the host (`~/.ssh`, browser data) is `skipped`, reported, never passed, does not fail the suite, and has its role covered by a fixture the test creates.
  The keychain canary reads a canary item from a throwaway keychain file that is never added to the search list. For that canary only, a sandboxed failure to obtain the item whose control obtained it maps to exit 10.
  The canaries cover: another home directory fixture, another task worktree, `/private/tmp`, `~/.ssh` and browser data listings, the throwaway keychain item, a write to a path outside the granted directories, a permitted write inside the work directory, direct egress to a loopback listener the test starts outside the sandbox on an ungranted port, an arbitrary loopback port, the working MCP relay route, and an ACP stdio round trip with zero non-JSON stdout lines, including during a denial, and the ownership canary: the sandboxed child's process group equals the wrapper's process ID. A failing ownership canary stops the build, because the ownership model of AC-AGENTS-SANDBOX-011.5 does not hold.
  Fixtures, the throwaway keychain, and the state root of the instance under test live in a marker-named root under the user's home, outside every denied temporary root. The marker name records its owning process, and a purge removes only marker roots whose owner is no longer running. The suite shall never read, modify, or unlock the user's login keychain. It shall delete the root on success, failure, panic, and SIGINT or SIGTERM, and purge stale roots when it starts. An attempt whose termination is unverified fails the suite and its marker root is left for the next owner-liveness purge.
  The suite locates the packaged provider through the environment variable `KANDEV_SANDBOX_CONFORMANCE_PLUGIN` (the directory of the reviewed Nono package). On darwin, an unset variable or a missing package fails the suite; only a non-darwin run reports the whole suite as skipped.
- **AC-AGENTS-SANDBOX-011.12:** A policy with an `agent_state` grant shall launch on darwin with the same exclusive-lock semantics as Linux.
- **AC-AGENTS-SANDBOX-011.13:** On darwin only ACP stdio transport is supported and verified. A native terminal start shall be refused with the typed Go error carrying the stable code `sandbox_transport_unsupported`; core owns this refusal, keyed by the host OS, in `startSandboxInteractive` (`agent/runtime/lifecycle/sandbox_native.go`), the single entry of every sandboxed native-terminal start. The refusal can follow MCP route preparation, which may already have captured an attempt; handling of a prepared attempt that is never dispatched is unchanged. Restart, cancellation, and cleanup are verified through the ACP path.
  A sandboxed host-utility probe or utility prompt for a sandbox-bound profile on a darwin core host shall be refused and shall never run: `prepareUtility` returns the existing generic `ErrSandboxLaunchUnsupported` before Prepare, keyed by the host OS. Other stdio protocols are not covered by darwin conformance in this version and keep their existing handling.
- **AC-AGENTS-SANDBOX-011.14:** The failure codes `sandbox_host_unsupported` and `sandbox_transport_unsupported` shall be the stable codes of the two typed refusals above. Both are refusals before startup, neither is a new status, category, or cause code, and the Settings availability blocker for `sandbox_host_unsupported` has localized text and a remedy. All new Execution details and settings copy shall exist in all seven shipped locales.
## Exclusions

On macOS, file, command, and network approvals, a Seatbelt log reader for denial reports, keychain-resident agent logins and a failure class for them, a conformance canary for CONNECT-relay egress, a failure class for provider profile-apply failure on a host whose probe passed (it stays the generic start failure), darwin/amd64 for the Nono provider, native terminal transport under a sandbox, and remote or SSH executors are excluded from this version. The keychain class, the CONNECT canary, and the profile-failure class are tracked in follow-up card `1ae5b8fa-67dd-4ea9-bae5-f6199e7ae9be`.

Git write access outside the work directory is also excluded. A sandboxed darwin agent in a linked Worktree cannot commit, because commits write to the common git directory outside the work directory; git fails with its own denial message. A Local main checkout whose git directory is inside the granted work directory is unaffected. The host git identity is not copied either, so commits fail with git's identity message until the identity follow-up lands. Derived common-git grants for linked worktrees, the host git identity copy, and the Seatbelt log reader are tracked together in follow-up card `1ae5b8fa-67dd-4ea9-bae5-f6199e7ae9be`.

Process-ownership hardening on darwin is excluded and tracked in follow-up card `0995aaaf-0b84-49b2-9eec-74e279ced0cf`: stopping a sandboxed process group left running after an agentctl restart (such an attempt stays `recovery_required`), a backend darwin containment object with its own `Contains`, `Empty`, and `Kill`, an authenticated agentctl stop operation carrying the recorded identity, sandboxed host-utility probes and discovery on darwin, and replacing agentctl's exit waiter with a reap-last leader model. A process that leaves the group by `setsid` or `setpgid` is an untracked residual that Execution details always states.

Also excluded and tracked in follow-up card `0995aaaf-0b84-49b2-9eec-74e279ced0cf` (items 9-11): a persisted launch-cause carrier and web mapping so the failure codes appear as localized launch-error text, a native-terminal refusal that precedes MCP preparation and cleans up the prepared attempt, support for sandboxed utility probes on darwin (refused in this version), codex-app-server and other non-ACP stdio protocols on darwin (neither refused nor verified; ACP is the only conformance-covered transport), per-reason granularity for `sandbox_host_unsupported` (one reason in this version; per-reason remedies need the probe reason on a route the launch path can read), a typed approval refusal reason string and channel reply (the refusal is the bare `ErrIneligible`), and darwin handling of agentctl's start receipt and `RetireDescendants` after a lost start reply (a darwin attempt whose start reply is lost is not recovered by the receipt and stays `recovery_required` through `ReconcileAttempt`).

The Linux behavior is unchanged: a description without an approval wire is still refused on Linux, a provider's `host_unsupported` answer keeps its existing handling on Linux, and Linux cgroup ownership is untouched.
