## Measured baseline

Nono 0.80.0 on macOS 27, Apple Silicon, measured 2026-10-25 with a harness shaped like a Worktree launch. The record lives in [the investigation](../../../plans/nono-sandbox-integration/investigation.md#macos-27-measured-baseline). Its default posture blocks other home directories, other worktrees, `~/.ssh`, browser data, and keychain items, and ACP stdio passes unchanged. Build records the exact provider option that removes Nono's default `/private/tmp` and `/private/var/folders` groups in the acceptance record.

## Host probe and admission

`executionCapabilities()` keeps its Linux predicate. On darwin it consults a probe result computed once, synchronously, before agentctl's listener starts. The probe is bounded at 5 seconds, so the backend's own agentctl health wait never overlaps it, and there is no pending state: `/identity` advertises `sandbox-launch.v1` only when the probe passed, and its absence is the only unsupported signal. `SurvivalCapabilities` becomes a value built after the probe instead of a package-level initializer. The result is immutable, so readers need no lock.

The probe follows AC-009.1: a fresh directory under the private state root, an unsandboxed control read, then `/usr/bin/sandbox-exec` with a deny-default profile granting the first file plus the minimum the reader needs to start (the reader binary and the system libraries it loads), and a trivial reader. It passes only when the control and granted reads succeed and the ungranted read fails with EPERM or EACCES. Any failed step, a timeout, or a panic leaves the capability absent and is logged with the failing step; no reason is exposed. The directory is removed and the child killed on every path. The probe checks no provider binary: the provider runtime is verified per attempt by core's runtime materialization (package checksum entry and copied bytes) and by the Settings availability check through `ReadSandboxRuntime`, so a provider install or upgrade after agentctl startup needs no new probe.

Admission is in `prepareExecution` (`backendapp/sandbox_runtime.go`): after the executor type validation and before the `protectedPorts` and `previousAttempt` steps and before `sandboxruntime` Prepare, where the transport and the executor's `/identity` are known (`sandboxLaunchAdmission.admit` in `sandbox_launch.go` holds no transport and is not the check site). For a darwin Local or Worktree executor it reads that executor's `/identity` and fails with a typed error carrying `sandbox_host_unsupported` when the read fails or the capability is absent, with no unwrapped retry. The refusal precedes provider compilation, previous-attempt reconciliation and attempt capture, so no attempt row, sandbox status or Execution details exist for it and no earlier attempt changes. The launch surfaces the typed error through the existing generic launch-failure handling; the stable code is logged and is the Settings blocker. The Tasks launch-error envelope, its categories and its cause codes are unchanged, no persisted-cause prefix is promised and the web client gets no mapping (deferred, see Exclusions). `sandbox_transport_unsupported` is a typed error the same way. `sandbox_creation.go` (task-creation admission) keeps its existing behavior and reads no capability. The Settings availability check (`sandbox_availability.go`) has no executor in its callback, so on a darwin backend it reads the capability of the backend's managed local agentctl; it reads on every call and caches nothing for darwin.

Provider refusal: `invokeSandboxProvider` (`plugins/sandbox_provider_dispatch.go`) currently replaces every provider error with `ErrSandboxProviderUnavailable`. It gains one branch: when the call error is the pluginsdk `host_unsupported` status (gRPC `FailedPrecondition`, message exactly `host_unsupported`), it returns a new typed sentinel `ErrSandboxHostUnsupported` that wraps `ErrSandboxProviderUnavailable` (so the normalize, report-read and learning-compile callers and the existing Linux `errors.Is` assertions behave as before); every other error keeps the existing opaque joined error. `sandboxruntime` Prepare maps that sentinel to `sandbox_host_unsupported` only when the core host is darwin; on any other host the sentinel is treated as `ErrSandboxProviderUnavailable`, so Linux admission and failure classes are unchanged. A state root under a denied temporary path is not a class of its own: creating the sandbox runtime refuses it with the existing `errSandboxRuntimeUnavailable`. The availability check (`sandbox_availability.go`) reports `sandbox_host_unsupported` as its blocker for the same conditions; its response shape is unchanged.

## Compilation environment

Neutral grants compile as on Linux. The provider emits grants and profile in sorted canonical path order, so identical effective grants and attempt paths give identical bytes.
- Per-attempt root: the directory `MaterializeRuntime` creates (`os.MkdirTemp` under the managed private state root, `attempt-` prefix, 0700, holding home, config, state, tmp) is split into a reserve step (creates the root, owns its removal until materialize commits) and a materialize step (renders into the reserved root, replacing the `MkdirTemp` inside `MaterializeRuntime`); a process-tree attempt reserves before the provider compiles, so `<root>/tmp` is known when the profile is built, and a failed preparation removes the reserved root. Prepare passes that path to the compile as the value of the `sandbox.child.tmp` reference, always on darwin and also when `agent_state` supplies HOME, config, and state; a kernel-container attempt calls reserve and materialize back to back after compile, so Linux directories, order and cleanup are unchanged; TMPDIR is the same directory, so environment and profile cannot disagree. No attempt reuses a root: a retry materializes a new one, and a failed preparation removes the directory it created. Nono's default groups that grant `/private/tmp` and `/private/var/folders` are not used. The sandbox runtime constructor refuses a base that resolves under a denied temporary path.
- Git: `GIT_CONFIG_NOSYSTEM=1` and the isolated HOME. No host configuration is read or copied.
- Keychain: no keychain path is ever granted and no bypass option is passed. Credentials come only from `environment_keys`, and an empty value counts as absent. No keychain failure class exists in this version.
- `agent_state`: darwin gets a `flock`-based `lockAgentState` equivalent to the Linux one, replacing the `!linux` refusal in `common/sandbox/agent_state_other.go` for darwin only.
- Transport: ACP stdio only. `startSandboxInteractive` (`agent/runtime/lifecycle/sandbox_native.go`) is the single entry of sandboxed native-terminal starts (passthrough and sessionless alike); on a darwin host it returns the typed `sandbox_transport_unsupported` error there, keyed by the host OS, so `SandboxPrepare` needs no transport argument. For passthrough agents with an MCP strategy, `sandboxMCPRoute` runs earlier and may already have captured an attempt (manager_passthrough.go); that prepared-but-undispatched attempt keeps its existing handling and this design does not claim an earlier refusal. `prepareUtility` (`backendapp/sandbox_utility_runtime.go`) gains an explicit refusal on a darwin core host, before Prepare, returning the existing generic `ErrSandboxLaunchUnsupported`: once agentctl advertises `sandbox-launch.v1`, `requireSandbox` no longer refuses, so without this branch utility probes would run as unverified process-tree attempts. Other stdio protocols are not specially handled.
- Network: unchanged topology. The child reaches only the provider's local proxy loopback port and the per-attempt MCP relay port; the provider's upstream proxy uses the exact-host core CONNECT relay.

## Ownership

There is one signalling owner on darwin: agentctl. There is no cgroup and no backend containment object; Execution details and the docs say so.

Agentctl starts the provider's wrapper with `Setsid` (`common/sandbox/process_unix.go`), so the wrapper leads a new session and group with `PID == GroupID == SessionID`. The existing owner route (`GET /agent/sandbox/owner`, `ProcessOwner.Supervisor`) reports it and the existing `BindOwner` binds it. Core sets `ownership_scope` at attempt capture from its own host OS (darwin gives `process_tree`), never from an executor answer. The `ownership_scope` in the private snapshot (`process_tree` here; absent reads as `kernel_container`; the public execution snapshot projects it read-only with the same default; an older backend ignores the unknown field) selects the darwin branches in `sandboxruntime`:
- `BindOwner`: the child identity is the supervisor identity (the wrapper is the owned child); the provider session identity is not required and the `Contains` and `IsDescendant` checks are replaced by a check `validateOwner` gains for a process-tree attempt: `Supervisor.GroupID == Supervisor.SessionID == Supervisor.PID` (today it checks only `SessionID == PID`). No group field is added to `AttemptOwner`; the scanned group is `Supervisor.PID`.
- `VerifyLive`: requires `ChildPID == SupervisorPID` and the live birth identity instead of a provider session identity.
- A darwin launch carries no containment identity; agentctl's `ConfigureContainment` is a no-op for it, keyed on the host OS being darwin and never on a nil containment, so a Linux launch without containment is still refused and the `Containment` calls in `canRemoveArtifacts`, `Close` and `ReconcileAttempt` are replaced by the group scan below. `RetireDescendants` and agentctl's start receipt are not changed for darwin (see Exclusions): a darwin attempt whose start reply is lost has no receipt-based recovery and stays `recovery_required` through `ReconcileAttempt`.

Stop is agentctl's existing manager stop (`waitForProcessExit`): SIGTERM to the group after the existing grace, SIGKILL after the existing terminate grace, including `reapRemainingProcessGroup` for members that outlive the leader. The wrapper is reaped only by agentctl's existing exit waiter; no second reaper or new stop route is added. The backend never signals.

Verification is backend-side and read-only: once the recorded supervisor identity is proven exited (the existing `recoveredSessionTerminated` precondition), a process-table reader scans for members whose group ID equals the recorded group, polling every 100 ms for at most 5 seconds, outside the manager lock (`m.mu`) that `ReconcileAttempt` and Prepare share, so the wait never blocks attempt capture. The reader calls `unix.SysctlKinfoProcSlice` directly and reads `Eproc.Pgid`, as `common/processidentity/processidentity_darwin.go` does (the backend darwin binary uses CGO; no libproc binding). Empty verifies termination. A surviving member at the bound, a read error, or a permission error returns the existing error path: `canRemoveArtifacts` fails, `Close` calls `markRecoveryRequired` (presented with the existing `ownership_unavailable` copy), files are retained, replacement stays blocked, and `Close` is retryable and idempotent.

After an agentctl restart nothing is re-adopted and no stop is attempted. `ReconcileAttempt` already refuses to release an attempt whose supervisor is not proven exited and leaves it `recovery_required`; when it is exited the darwin branch runs the same scan and finalises as stopped only on an empty group. A live process left behind is unmanaged until the operator stops it, and a group ID reused by an unrelated process keeps the scan non-empty (fail closed); both are declared residuals, with stop-after-restart tracked in follow-up card `0995aaaf-0b84-49b2-9eec-74e279ced0cf`. A process that calls `setsid` or `setpgid` leaves the group and is an untracked residual that Execution details always states. The child staying in the wrapper's group is not assumed: the ownership canary of AC-009.11 proves it, and a failure stops the build.

## Approvals, reports, status

Behavior is keyed by the attempt's `ownership_scope`, so nothing about Linux changes. For a `process_tree` attempt, core creates no approval listener, secret, or pending row whatever the provider description carries, and the attempt compiles without an approval webhook; a darwin description without an approval wire is admitted (Linux keeps refusing it through the existing missing-wire check). A darwin artifact that references `sandbox.approval.endpoint` fails compilation through the existing missing-reference path. No proto field, approval-kind declaration, or legacy-declaration rule is added. `RecordApproval` (`agent/sandbox/approval_store.go`), the single place where a request becomes a row, refuses a `process_tree` attempt with the existing bare `ErrIneligible`, writes no row, and does not wait. No reason string or reply shape is added; the approval channel's existing handling of a `RecordApproval` error applies unchanged, and because a process-tree attempt has no listener the refusal is the defence in depth reached by the service-level test. Every other attempt keeps its existing path and reasons. The compiled prefix selects Nono's non-interactive denial behavior; conformance asserts zero non-JSON stdout lines during a denial.

Reports: a `process_tree` attempt has no report. `captureReport` and `RefreshReport` in `sandboxruntime/report.go` and the report step in `Close` return early for the scope without calling the provider's report read and without writing a row, so no envelope exists and the write fence on a previous version (`ReadCapturedReport` in `agent/sandbox/report_store.go`) is never reached. `ErrNotFound` from `ReadCapturedReport` for such an attempt is the normal state, not a failure. Execution details shows the filesystem-denials-unavailable notice for `process_tree` attempts, chosen by the `ownership_scope` projected in the execution snapshot rather than by a report, instead of the empty-denials sentence. With no report the learning review offers no proposals. `ReportData` and stored digests are unchanged and no `validReportEnvelope` use is added. Status follows AC-AGENTS-SANDBOX-008.2; whether Nono 0.80.0 yields darwin status evidence is decided by Build and recorded as `active_status_evidence: supported|unsupported`. Without evidence the status is unknown.

## Failure classes and surfaces

Two stable codes with the base prefix, both typed refusals: `sandbox_host_unsupported` (one reason) is raised before startup in `prepareExecution`, before any attempt exists; `sandbox_transport_unsupported` is raised in `startSandboxInteractive` and can follow MCP route preparation (see Transport). Neither sets an attempt status. They reach the user through the existing generic launch failure; the codes are logged, and `sandbox_host_unsupported` is also the Settings blocker.

| Class | Surface | Intent of the text | Remedy |
| --- | --- | --- | --- |
| `sandbox_host_unsupported` | Generic launch failure and log, Settings availability check | This host cannot confine agents | Restart the agent runtime, or use a supported host or provider |
| `sandbox_transport_unsupported` | Generic launch failure and log | Native terminal is not available under a sandbox on this host | Use the ACP transport |

Execution details gains the ownership scope line, approvals shown as not supported, and the filesystem-denials-unavailable notice. All new copy goes through `t()` in all seven shipped locales. Component tests cover each new state.

## Conformance

The Kandev suite, `apps/backend/internal/plugins/sandbox_darwin_conformance_test.go`, runs each AC-009.11 canary through a real core launch and a control, gated on `runtime.GOOS == "darwin"`; elsewhere it reports skipped. On darwin it locates the reviewed Nono package through `KANDEV_SANDBOX_CONFORMANCE_PLUGIN` and fails, never skips, when the variable or package is missing. Outcome mapping, canary list, keychain exit mapping, fixtures root, marker naming, and cleanup are those of AC-009.11. Stale marker roots (keychains and state roots) are purged by owner-liveness at suite start, which bounds the hard-kill case; an attempt with unverified termination fails the suite and keeps its marker root for that purge. The suite adds the ownership canary. The test creates a replacement fixture for any skipped real target. The provider repository suite runs the same canaries against the provider-compiled profile and is the artifact release gate. The macOS version that ran each suite is recorded with its results in the acceptance record.

## Concurrency and errors

Per-attempt directories are keyed by attempt and never shared or reused. Cleanup is idempotent and follows verified termination only. The probe is single-run and immutable; a failure omits the capability for the process lifetime. Concurrent starts read the immutable capability and each own a distinct group. Linux behavior (AC-009.10) is untouched: every darwin branch is keyed by the host OS or the attempt's `ownership_scope`, and the Linux tests run unmodified. Every refusal has a stable class and no unwrapped retry.
